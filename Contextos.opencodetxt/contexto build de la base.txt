================================================================================
2. COMO SE ARMA LA BASE (el loader)
================================================================================
El estilo del repo es "END ; / DELIMITER ;". El cliente mysql NO entiende eso
tal cual: al llegar a "DELIMITER ;" con un bloque sin cerrar, lo mete como SQL
y manda ERROR 1064 en cascada. Por eso el loader:

- Simula el cliente linea por linea (delimitador activo + buffer con SQL real).
- Un buffer que trae solo comentarios o blancos cuenta como vacio: ahi si
  reconoce el comando DELIMITER.
- Cuando el DELIMITER llega con SQL acumulado, reescribe la ultima sentencia
  del bloque ("END ;" -> "END //") para que el buffer se vacie justo ahi.
- Si el buffer ya estaba vacio no toca nada (hay bloques que se cierran solos
  con un "//" suelto, y reescribirlos los rompia).

Comandos:
  python3 /tmp/opencode/load_modules.py BALBU_TECH_TEST /tmp/opencode/build.log 2
  mysql -uroot -plinux01 -e "DROP DATABASE IF EXISTS BALBU_TECH_TEST; \
        CREATE DATABASE BALBU_TECH_TEST CHARACTER SET utf8mb4;"

Se corren 2 pasadas a proposito: la 1 crea todo lo que puede y la 2 pega los
triggers/tables que apuntan a tablas que recien se crean despues (ver punto 4).

================================================================================
4. ERRORES QUE QUEDAN (y estan bien)
================================================================================
Pasada 1 (desde cero): 21 errores, todos 1146/1005 = "tabla todavia no
existe". Pasan porque los archivos se cargan en orden numerico y hay triggers
de 19- COMPRAS que apuntan a DETALLE_COMPRA (22-), 19.6/25 que apuntan a
tablas de 22/23, y 6- AUDITORIA que apuntan a PRODUCTOS (9-). La pasada 2 los
crea todos: ningun error de sintaxis.

Pasada 2 (sobre BD existente): 110 errores, todos de tipo "ya existe"
(1050/1061/1304) + 15 avisos 1644 de semillas ("ESTA MARCA YA EXISTE",
"ESTE METODO DE PAGO YA EXISTE", un telefono de CLIENTES). Son amables: el SP
captura la duplicidad y solo avisa; los datos quedan bien.

Diferencia contra la BD real: BALBU_TECH tiene 11 SPs que ya no estan en el
repo (1_SP_BUSCAR_CATEGORIAS, SP_CREAR_USUARIO, SP_ELIMINAR_BONO, ...) y un
trigger viejo 14_TR_VALIDAR_FECHA_BONO. Es deuda historica de la BD real, no
del build.
